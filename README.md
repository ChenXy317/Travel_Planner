# 旅行规划

本地单用户旅行规划助手。用中文说出城市、天数、人数、偏好和预算。服务用 LangChain `create_agent` 让模型节点和工具节点交替进行：模型决定下一步，地理编码、天气、地点、搜索摘要、路程和金额只来自工具。确认保存后，计划文档按已保存的行程填固定六节模板，数字不经过模型重写。设计见 [PLAN.md](PLAN.md)。

演示可以发这句：

> 下周五起，两个人去青岛玩三天，想看海和博物馆，酒店一晚 400，预算 3000。排好之后给我一份计划文档。

## 运行

```bash
cp .env.example backend/.env   # 已有 backend/.env 就不用覆盖
./start.sh
```

`start.sh` 用 uv 安装 Python 3.12 和依赖，在 `127.0.0.1:8001` 起一个 uvicorn worker，再在 `http://127.0.0.1:5174` 起 Vite。只开一个 worker，进程内的请求闸门才不会裂开。脚本退出时会关掉 API。

密钥只放在 `backend/.env`。

## 对话模型

`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY` 是 OpenAI 兼容的对话接口，也是页面设置的初始值。当前测试默认是 Ollama Cloud：`https://ollama.com/v1`，模型 `gemma4:31b-cloud`。这三项都留空时，地址回退到本机 `http://127.0.0.1:11434/v1`。页眉「模型」可以改地址、模型名和密钥；密钥不会从接口返回，不填表示保持原值，换地址时如果密钥仍是环境变量里的那一份会丢掉。改动只在进程内存里，重启后回到 `backend/.env`。

对话原文和工具摘要会发给这个模型接口，也会按工具发给下面四个数据源。

## 搜索

`SEARCH_API_KEY` 是 Brave 的 `X-Subscription-Token`。留空时搜索工具直接失败，不会去打网络。主路径是 LLM Context；账号没有这个接口时，自动改用 Web Search，交回的标题、链接和片段形状相同。2026 年起 Brave 新账号要绑卡才有每月搜索额度。演示时如果看到「搜索未授权」或套餐错误，先核对额度和订阅，不一定是代码坏了。

## 限制

- 最多两座城市、5 天、每天 3 个站点。不订机票、火车票、酒店或门票。
- 预报数据最多覆盖 16 天，工具只接受 1 到 5 天。
- 路程来自 OSRM 演示服务，不保证可用。失败会写在工具卡上，不会用直线距离冒充。
- 开放时间和价格只抄搜索摘要。摘要里没有的价格保持未知，不用城市均价填上。
- 金额用整数分。带链接的价格必须对得上这次会话里出现过的搜索链接。

## 署名

天气来自 Open-Meteo，须署名，许可为 CC BY 4.0。地点来自 OpenStreetMap 贡献者，经由 Overpass 查询。搜索由 Brave Search 提供。
